# PetLog

ქართული პირადი სივრცე შინაური ცხოველის ჯანმრთელობისთვის, მოგონებებისთვის, პარტნიორების შეთავაზებებისა და GPS სეირნობისთვის. React 19, TypeScript, Supabase Auth / Postgres / Storage, Leaflet და QR კოდები.

## Supabase-ის გამართვა

პროექტი დაკავშირებულია მომხმარებლის მოწოდებულ Supabase პროექტთან. ბრაუზერში გამოიყენება მხოლოდ საჯარო publishable key; პირად მონაცემებს RLS იცავს. სერვისის ადმინისტრატორის გასაღები აპში არ გამოიყენება.

1. Supabase Dashboard → **SQL Editor** → **New query**. ჩასვით და გაუშვით [supabase/schema.sql](./supabase/schema.sql) **სრულად**. ეს არის ზუსტი, გასაშვები SQL: ქმნის ცხრილებს, მფლობელისა და დადასტურებული ელფოსტის RLS წესებს, დახურულ `pet-media` საცავს, ვაუჩერის გაცემის / განაღდების ფუნქციებსა და GPS მანძილის გადამოწმებას. საცავი და ავტორიზაციის სტანდარტული სქემები Supabase-ის მიერ უნდა იყოს შექმნილი.
2. **Authentication → Sign In / Providers → Email**: ჩართეთ Email provider, Sign up და **Confirm email**. Email OTP length დააყენეთ **6**-ზე; პროექტში თავდაპირველად 8 იყო მითითებული.
3. **Authentication → URL Configuration**: Site URL — `https://mariamsajaia1521.github.io/Abby/`. Redirect URLs-ში დაამატეთ იგივე მისამართი და ლოკალური განვითარებისას `http://127.0.0.1:5173/` და `http://127.0.0.1:4173/`.
4. **Authentication → Emails → SMTP Settings**: დააკავშირეთ **Custom SMTP**. ამ უფასო პროექტში წერილის სათაურისა და შიგთავსის შეცვლა SMTP-ის დაკავშირების შემდეგ იხსნება. ქვემოთ მოცემულია უფასო Gmail კავშირის ნაბიჯები. SMTP-ის შეერთებამდე Supabase იყენებს თავის სტანდარტულ წერილს, რომელიც მხოლოდ დადასტურების ბმულს შეიცავს.
5. **Authentication → Emails → Templates → Confirm sign up**: SMTP-ის შენახვის შემდეგ ჩასვით [მზა ქართული წერილი](./supabase/confirm-signup.html). წერილი შეიცავს როგორც 6-ნიშნა `{{ .Token }}`-ს, ისე `{{ .ConfirmationURL }}` ბმულს. კოდი ხელმისაწვდომია სხვა მოწყობილობაზეც; PKCE ბმული გახსენით რეგისტრაციის იმავე ბრაუზერში. სათაური: `დაადასტურე შენი ელფოსტა — PetLog`.

არსებული SQL მონაცემები არ იშლება. არცერთი გამოგონილი ცხოველი, აცრა, კონტაქტი, მოგონება ან პარტნიორის შეთავაზება არ იქმნება. პროფილის ავტომატური შექმნისას ინახება მხოლოდ რეალური Auth მომხმარებლის ID და ცარიელი სახელი.

## უფასო Gmail SMTP კავშირი

ეს ვარიანტი იყენებს თქვენს არსებულ Gmail ანგარიშს; დამატებითი დომენი არ სჭირდება. მასზე ვრცელდება [Gmail-ის გაგზავნის დღიური ლიმიტები](https://support.google.com/mail/answer/22839?hl=en). Supabase-ის SMTP ფორმაც მიუთითებს, რომ Gmail პირადი წერილებისთვისაა განკუთვნილი და მიწოდება შეიძლება განსხვავდებოდეს სპეციალიზებული ტრანზაქციული სერვისისგან.

1. Google Account → **Security → 2-Step Verification** ჩართეთ. შემდეგ გახსენით [App Passwords](https://myaccount.google.com/apppasswords), აპის სახელად ჩაწერეთ `PetLog` და შექმენით ცალკე პაროლი. [Google-ის ოფიციალური ინსტრუქცია](https://support.google.com/accounts/answer/185833?hl=en) განმარტავს საჭირო პირობებსა და შემთხვევებს, როცა App Passwords მიუწვდომელია.
2. Supabase-ის **Authentication → Emails → SMTP Settings** გვერდზე ჩართეთ **Enable custom SMTP** და შეავსეთ:

| ველი | მნიშვნელობა |
| --- | --- |
| Sender email address | თქვენი რეალური Gmail მისამართი |
| Sender name | `PetLog` |
| Host | `smtp.gmail.com` |
| Port number | `587` |
| Username | იგივე სრული Gmail მისამართი |
| Password | Google-ში ახლად შექმნილი 16-სიმბოლოიანი App Password, გამოტოვებების გარეშე |

SMTP-ის ჰოსტისა და პორტის [Google-ის ინსტრუქცია](https://support.google.com/mail/answer/7104828).

3. App Password შეიყვანეთ უშუალოდ Supabase-ის **Password** ველში და შეინახეთ **Save changes**-ით. ჩვეულებრივი Google პაროლი აქ არ გამოიყენება; SMTP პაროლი კოდში, GitHub-ში ან frontend გარემოს ცვლადებში არ ინახება.
4. დაბრუნდით **Templates → Confirm sign up** გვერდზე, შეინახეთ ქართული სათაური და [წერილის შიგთავსი](./supabase/confirm-signup.html).
5. აპში დააჭირეთ **ხელახლა გაგზავნა**, რათა მიიღოთ უკვე ახალი პარამეტრებით შედგენილი წერილი. დადასტურების შემდეგ ცარიელ ანგარიშში პირველი მეგობრის დამატება დაიწყება.

## გაშვება

საჭიროა Node.js 24+.

```sh
npm install
npm run dev
```

მისამართი: `http://127.0.0.1:5173/`. Windows-ზე ან Linux-ზე იგივე ბრძანებები მუშაობს. macOS-ზე საჭიროებისას მიუთითეთ `OPENSSL_CONF=/dev/null`, თუ ლოკალური Node ინსტალაცია OpenSSL-ის კონფიგურაციაზე წვდომას ითხოვს.

```sh
npm test
npm run build
npm start
```

საწარმოო build-ის ლოკალური მისამართია `http://127.0.0.1:4173/`. [PetLog.command](./PetLog.command) ხსნის ამავე აპს. [server.ts](./server.ts) მხოლოდ frontend ფაილებს ემსახურება; პერსონალური მონაცემების მეორე, ლოკალური ავტორიზაციის სისტემა არ არსებობს. ძველი ლოკალური არქივი არ შეცვლილა და ავტომატურად არ იმპორტირდება.

სხვა Supabase პროექტზე გადასასვლელად გადააკოპირეთ [.env.example](./.env.example) `.env.local` ფაილად და შეავსეთ `VITE_SUPABASE_URL` და `VITE_SUPABASE_PUBLISHABLE_KEY`. ასევე მხარდაჭერილია საჯარო legacy `VITE_SUPABASE_ANON_KEY`. ეს არის build-time მნიშვნელობები: შეცვლის შემდეგ საჭიროა თავიდან build. `.env.local` Git-ში არ იგზავნება. არასოდეს მიუთითოთ `service_role` ან `sb_secret_` გასაღები.

## წვდომის ნაკადი

- ახალი სტუმარი ხედავს მხოლოდ შესვლის / რეგისტრაციის ეკრანს. URL ფრაგმენტი ან ძველი ბრაუზერის ჩანაწერი ავტორიზაციას ვერ ჩაანაცვლებს.
- რეგისტრაციის შემდეგ ჩანს მხოლოდ ელფოსტის დადასტურების ეკრანი. კოდი მოწმდება `Supabase Auth.verifyOtp`-ით. ხელახალი გაგზავნა იზღუდება როგორც ინტერფეისში, ისე Supabase-ის მიერ.
- სესიის მომხმარებელი ხელახლა მოწმდება Auth სერვერთან. დაუდასტურებელი ელფოსტა RLS-ის დონეზეც ბლოკავს პირად მონაცემებს.
- დადასტურებულ მომხმარებელთან `pets` ცარიელია → იწყება პირველი მეგობრის სამნაბიჯიანი დამატება, გამოტოვების ღილაკის გარეშე. საჭიროა საკუთარი ფოტო, სახელი, სახეობა, სქესი, ჯიში, დაბადების თარიღი და წონა; მიკროჩიპი არჩევითია.
- დაფა იხსნება მხოლოდ წარმატებული ატვირთვისა და `pets` ჩანაწერის შენახვის შემდეგ. ქსელის ან SQL-ის შეცდომა ცარიელ ანგარიშად არ განიხილება.

## პარტნიორის სტენდების მართვა

რეალური განაცხადები იხილეთ Supabase Table Editor-ის `partner_applications` ცხრილში. განხილვის შემდეგ ადმინისტრატორი ქმნის რეალურ `partner_booths` ჩანაწერს, მიუთითებს შეთავაზებას, ვადასა და სამიზნე პირობებს და მხოლოდ შემდეგ რთავს `is_active`-ს. შეთავაზება ავტომატურად არ იქმნება განაცხადიდან. `owner_id` მიაბით რეალური ბიზნესის ოპერატორის Auth ID-ს. `species` / `breeds` ცარიელი სია ნიშნავს ყველა სახეობას / ჯიშს, ასაკი კი თვეებში იზომება. გამოქვეყნებული შეთავაზებების მართვა მხოლოდ ადმინისტრატორის სანდო გარემოდან ხდება.

QR შეიცავს `{ "type": "petlog-voucher", "version": 1, "code": "…" }` მონაცემს, ბაზაში შენახული უნიკალური კოდით. პარტნიორის ოპერატორი თავის დადასტურებულ სესიაში იძახებს `supabase.rpc('redeem_voucher', { p_code: scannedCode })`-ს. ფუნქცია ამოწმებს სტენდის მფლობელობას, მოქმედების ვადასა და აქტიურ სტატუსს; ხელმეორედ განაღდება იბლოკება. ეს API ხელმისაწვდომია ოპერატორის POS / სკანერის ინტეგრაციისთვის. მომხმარებელს ვაუჩერის თვითგანაღდების უფლება არ აქვს. თითო ანგარიშზე თითო შეთავაზება გაიცემა ერთხელ; გაუქმება ახალ კოდს არ ქმნის.

## GPS და PawCoins

მდებარეობა მოითხოვება მხოლოდ „სეირნობის დაწყება“-ზე დაჭერის შემდეგ, HTTPS ან localhost გარემოში. რუკა რეალურ კოორდინატამდე ცარიელია. Leaflet იყენებს OpenStreetMap-ის ფონურ რუკას და მის ატრიბუციას; პერსონალური მარშრუტი სხვა მომხმარებლებთან არ ქვეყნდება. რუკის ფილების მომწოდებელი იღებს მოთხოვნილი რუკის არეალის მონაცემებს; მაღალი დატვირთვისას გამოიყენეთ კომერციული tile provider.

ზუსტი GPS წერტილები პერიოდულად ინახება და გვერდის გადატვირთვის შემდეგ შესაძლებელია შენახული სეირნობის გაგრძელება. ინტერნეტის დაკარგვისას დაუშენახავი ნაწილი რჩება მიმდინარე გვერდის მეხსიერებაში და დასრულებისას ხელახლა იგზავნება. გვერდის დახურვისას ბოლომდე დაუშენახავი ნაწილი შეიძლება დაიკარგოს, ამიტომ გამოჩნდება ბრაუზერის გაფრთხილება. მობილური ბრაუზერის დახურვის ან ფონზე შეჩერებისას უწყვეტი ჩაწერა გარანტირებული არ არის.

1 კმ = 100 PawCoins; ყოველი დასრულებული სეირნობისთვის გამოიყენება `floor(distance_m / 10)`. PostgreSQL ხელახლა ითვლის Haversine მანძილს, ამოწმებს GPS სიზუსტეს, დროის თანმიმდევრობას, რეალურ სეირნობის სიჩქარეს და ადრე შენახულ მარშრუტს. კლიენტის გამოგზავნილი მანძილი იწერება თავიდან, ქულა კი generated column-ია. დასრულებული სეირნობის შეცვლა აკრძალულია; წაშლა შლის მის ქულებსაც. ჩვეულებრივი ბრაუზერის GPS მონაცემების გაყალბების სრულად გამორიცხვა შეუძლებელია; ფინანსური ჯილდოების გამოსყიდვა დამატებით სერვერულ ანტიფროდს მოითხოვს.

## შემოწმება და გამოქვეყნება

`npm test` ამოწმებს სავალდებულო წვდომის საფეხურებს, GPS წერტილებს და იზოლირებულ PostgreSQL გარემოში SQL სქემას, RLS-სა და დაცულ მოქმედებებს. ეს ტესტები რეალურ Supabase პროექტში ანგარიშებს ან ცხოველებს არ ქმნის. `npm run build` ასრულებს TypeScript შემოწმებას და საწარმოო build-ს.

[GitHub Pages workflow](./.github/workflows/pages.yml) გამოქვეყნებისას უშვებს ტესტებს, ამოწმებს ტიპებს და აშენებს აპს `/Abby/` ბაზის მისამართით. საჭიროებისას repository Variables-ში მიუთითეთ `VITE_SUPABASE_URL` და `VITE_SUPABASE_PUBLISHABLE_KEY`; ცარიელი მნიშვნელობებისას გამოიყენება მომხმარებლის მოწოდებული საჯარო პროექტის კონფიგურაცია. ჩართული Auth email redirects აუცილებლად უნდა ემთხვეოდეს გამოქვეყნებულ მისამართს. კოდის ლოკალური ცვლილება თავისთავად GitHub Pages-ზე არ ქვეყნდება — საჭიროა `main`-ზე push ან workflow-ის გაშვება.
